# Steam Market Intelligence

Steam 공개 데이터를 Python·SQL로 분석하고 Tableau로 시각화하는 데이터 분석·BI 취업 포트폴리오 프로젝트입니다.

## 목표

신작 PC 게임 출시를 검토하는 가상의 중소 게임 퍼블리셔가 장르·가격·출시 시점·경쟁 게임을 탐색할 수 있는 시장 분석 대시보드를 만듭니다. 실제 기업 의뢰나 사업 성과가 있는 프로젝트는 아닙니다.

- 기술 계획: Python·Pandas → PostgreSQL·SQL → Tableau
- 최종 산출물: 대시보드 3개, 재현 가능한 처리 코드·SQL, 시장 분석 보고서, 취업용 프로젝트 소개 자료
- 공개 범위: 데이터 출처와 라이선스 검토 후 결정

## 현재 상태

2026-10-15 기준 프로젝트 폴더와 초기 문서를 준비했습니다. 데이터 다운로드·API 수집·분석 코드·DB 적재·Tableau 제작은 아직 실행하지 않았습니다. 의존성 설치와 실행 명령은 구현 단계에서 실제 환경을 확인한 뒤 추가합니다.

다음 작업은 **1단계 데이터 확보·분석 설계**입니다. 단계별 목표·범위·완료 기준·추천 모델을 안내하고, 사용자가 모델을 선택하고 진행 의사를 밝힌 뒤 해당 단계만 실행합니다. 폴더 준비는 데이터 수집이나 분석 실행 승인을 뜻하지 않습니다.

| --- | --- | --- |

| 3. Tableau 제작 | 대시보드 3개, 필터·액션·툴팁 | 주요 수치가 SQL과 일치하고 필터·동작 확인 |

Steam 프로젝트를 먼저 완성한 뒤 부족한 직무 역량에 맞춰 후속 프로젝트를 선택합니다.

## 분석 질문 후보

실제 데이터의 컬럼·품질을 확인하기 전의 후보입니다.

1. 어떤 장르에 출시 게임이 많이 몰려 있는가?
2. 가격과 긍정 평가 비율은 어떤 관계인가?
3. 출시 시기별 공급량과 평가 지표는 어떻게 다른가?
4. 인디와 대형 퍼블리셔 게임을 데이터로 구분하고 비교할 수 있는가?
5. 공급량이 적으면서 평가 지표가 좋은 세부 장르는 무엇인가?

질문별로 집계 단위·대상 범위·분모·제외 조건·기준 시점을 정의합니다. 인디·기업 규모 등 필요한 필드가 없거나 비교 조건을 맞출 수 없으면 질문을 수정합니다.

## 데이터 후보와 확인할 사항

- 기본 후보: [Steam Games Dataset 2025](https://www.kaggle.com/dsv/11017460). 원본 파일·실제 행 수·컬럼·라이선스·스냅샷 시점은 아직 검증하지 않았습니다.
- 보조 후보: [Steam 공개 리뷰 조회 공식 문서](https://partner.steamgames.com/doc/store/getreviews). 추가 리뷰 분석이 필요할 때만 사용 조건·호출 범위를 정해 검토합니다.
- 우선 고정된 스냅샷으로 재현 가능한 분석을 완성합니다. 최신 데이터와 API 수집은 후속 확장 후보입니다.
- 확인 항목: 출처와 이용·재배포 조건, 수집 기준 시점, 게임 ID 유일성, 무료·미출시·DLC 포함 여부, 중복·결측·자료형, 복수 장르·태그 구조, 가격 시점·통화, 리뷰 지표 정의.

## 대시보드 계획

| 화면 | 내용 |
| --- | --- |
| 시장 전체 현황 | 게임 수, 연도별 출시 추이, 장르별 공급량, 가격·평가 분포 |
| 장르·가격 경쟁 분석 | 장르별 공급량·평가 지표, 가격대 분포, 비교 가능한 경쟁작 |
| 신작 출시 기회 탐색 | 공급량과 공개 평가 지표를 조합한 조사 후보와 경쟁 게임 상세 탐색 |

차트와 KPI는 데이터 검증 후 확정합니다. 주요 지표는 SQL에서 계산하고 Tableau 표시값과 대조합니다.

## 분석·검증 원칙

- 리뷰 수를 판매량·매출로 표기하지 않습니다. 추정 소유자 수도 실제 매출로 단정하지 않습니다.
- 상관관계를 인과로 해석하지 않으며, 공급량이 적다는 이유만으로 수요나 성공 가능성이 높다고 결론 내리지 않습니다.
- 복수 장르의 중복 집계, 소표본, 리뷰 수 차이, 출시 후 경과 기간을 드러냅니다.
- 가격의 기준 시점·통화를 명시합니다. 공개 데이터만으로 마케팅 비용·수익성·구매 전환을 설명하지 않습니다.
- 데이터 출처·스냅샷·정제 및 제외 기준·검증 결과를 기록합니다. 원자료는 라이선스 확인 전 Git에 올리지 않습니다.
- 계획한 기술과 검증된 결과를 구분하고, 실제로 수행한 작업만 포트폴리오에 기재합니다.
