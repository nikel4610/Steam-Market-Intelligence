# Steam Market Intelligence

**개인·소규모 게임 제작자를 위한 Steam 시장 분석과 월간 브리핑.**

무엇을 만들지 고민하는 제작자가 최신 시장 흐름과 경쟁작의 이용자 반응을 이해하고, 아이디어를 검토하며, 제작 전에 검증할 질문을 정하도록 돕습니다. 바이브 코딩 등으로 제작에 접근한 사람도 근거를 이해하고 활용할 수 있도록 설계합니다.

데이터 분석·시각화가 주 목적입니다. 문제 정의 → 데이터 확보·정제 → SQL 분석 → 검증 → 시각화 → 인사이트 → 실행 계획 제안까지 연결합니다. 실제로 사용할 수 있는 시장 브리핑 서비스가 최종 목표이며, 현재 서비스가 운영 중이라는 뜻은 아닙니다.

## 현재 상태와 범위

2026-10-15 기준 기획 단계입니다. 데이터 수집·분석·대시보드 제작·서비스 배포는 아직 시작하지 않았습니다. 실행 방법과 공개 결과물은 구현 및 검증 후 추가합니다.

- 계획 기술: Python·Pandas → PostgreSQL·SQL → Tableau.
- 핵심 산출물: 월간 시장 브리핑, 탐색용 대시보드, 심층 분석 보고서, 기획 검토서 양식, 재현 가능한 코드·SQL·검증 기록.
- 목표 기간: 2018년부터 확보 가능한 최신 완료 월까지. 지표별 실제 확보 기간은 데이터 검증 후 확정합니다.
- 제외: 자동 게임·콘셉트 추천, 개인별 구매·플레이 확률 예측, 판매량·유행 예측 모델 학습, 챗봇. 분석 결과에 따른 실행 제안과 통계적 검증은 포함합니다.
- 조건부 확장: 보유·미플레이 분석, 과거 이용·가격 지표, 출시 후 동일 기간 비교. 필요한 자료가 부족하면 핵심 프로젝트를 지연시키지 않고 제외 이유를 기록합니다.
- 로그인·결제·별도 웹앱은 필수 범위가 아닙니다. 공개 방식은 데이터 이용 조건과 사용자 검토 후 선택합니다.

## 사용자와 의사결정

| 상황 | 사용자 질문 | 제공할 근거와 다음 행동 |
| --- | --- | --- |
| 아이디어 탐색 | 최근 무엇이 달라졌는가? | 월간 변화, 지속되는 흐름, 대작 집중 여부 |
| 아이디어 검토 | 비슷한 게임은 어떤 반응을 얻었는가? | 비교군의 분포·평가·반복되는 요구 |
| 제작 전 검증 | 무엇을 먼저 확인해야 하는가? | 위험 요인과 프로토타입·플레이 테스트 가설 |

“잘 팔릴지” 또는 “재미있을지”를 보장하지 않습니다. 시장 자료로 확인한 사실과 실제 게임 테스트가 필요한 부분을 구분합니다. 기획 수정·추가 조사·진입 보류도 유효한 결과입니다. 기업 의뢰·매출 개선 등 관측하지 않은 성과를 주장하지 않습니다.

## 핵심 분석 질문

중심 질문: **세부 장르의 흥행 변화는 여러 게임에 걸친 지속적인 흐름인가, 소수 대작·공급 증가·특정 시기의 영향인가? 이용자 평가는 어떤 기획 과제를 보여주는가?**

| 영역 | 분석 질문 | 지표·시각화 후보 |
| --- | --- | --- |
| 연도별 흥행 | 그해 흥행한 게임과 그해 출시된 게임은 어떻게 다른가? | 공식 차트 등급, 연속 진입, 신작·기존작 구성 |
| 월별 시장 | 장르·플레이 요소의 반응과 출시량은 함께 변하는가? | 출시 수, 차트 내 구성비, 월별 추이·히트맵 |
| 변화의 범위 | 여러 게임의 변화인가, 일부 대작의 영향인가? | 게임별 중앙값·분포, 상위 작품 집중도, 제외 전후 비교 |
| 평가·경쟁작 | 흥행과 만족은 일치하며 무엇이 반복해서 언급되는가? | 평가율·리뷰 수, 유사 게임 비교, 리뷰 주제 |
| 계절·사건 | 반복되는 월별 패턴과 사건 전후 변화가 있는가? | 기간별 비교, 사건 표시, 대안 설명 검토 |
| 이용 — 조건부 | 보유와 실제 플레이 기록 사이에 어떤 차이가 있는가? | 표본 내 미플레이 비중, 플레이 시간 분포 |

세부 분류는 대분류·하위 장르·플레이 방식·핵심 요소·테마·표현 방식으로 나누고 원본 태그와 연결합니다. 예: 생존 제작 × 온라인 협동. 표본이 부족하면 상위 분류로 묶거나 판단을 보류합니다. 원자료로 확인할 수 없는 개발비·팀 규모·플레이 경험을 임의로 추정하지 않습니다.

## 차별화와 분석 원칙

1. **인기작과 보통 작품을 함께 봅니다.** 전체 합계·평균만 쓰지 않고 분포와 집중도를 확인합니다. 적은 반응을 수익성 실패로 단정하지 않습니다.
2. **비교군을 설명합니다.** 포함·제외 이유를 보여주고, 유사 장르·플레이 방식·출시 시기·무료 여부 등을 맞춥니다. 사용자가 비교 대상을 바꿔 결과를 확인하게 합니다.
3. **결론의 안정성을 확인합니다.** 최소 리뷰 수, 무료 게임, 대표 흥행작, 비교 기간에 따라 결론이 바뀌는지 검토합니다. 기준값은 데이터 확인 후 정합니다.
4. **리뷰에서 검증 과제를 찾습니다.** 성능·게임성·콘텐츠·가격·현지화 등의 주제를 복수로 분류하고, 게임 간 반복·시기별 지속 여부를 확인합니다. 표본을 사람이 검토하며 분류 정확도를 검증하지 않은 결과를 확정 사실로 쓰지 않습니다.
5. **불확실성과 반대 사례를 공개합니다.** 표본 수·관측 기간·누락·출처·지표 정의를 함께 제공합니다.

### 지표의 경계

- 공식 매출 차트 등급, 리뷰 반응, 평가, 실제 이용은 별도 지표입니다. 리뷰 수를 판매량으로, 추정 소유자 수×현재 가격을 매출로 표시하지 않습니다.
- 월별 신작 차트의 출시 초기 매출 기준과 해당 월 전체 게임 매출을 구분합니다. 연도·버전별 차트 선정 기준과 DLC 포함 여부를 확인합니다.
- 복수 태그의 중복·분모를 정의합니다. 차트 진입률은 전체 출시 분모와 차트 대상 범위를 맞출 수 있을 때만 계산합니다.
- 완료 연도끼리 비교하며 최신 연도는 전년 동기간과 비교합니다. 부분 월·결측 월은 0으로 처리하지 않습니다.
- 현재 태그·가격·누적 평가를 과거 시점의 값으로 쓰지 않습니다. 과거 리뷰의 수정·삭제, 판매 중단 게임 누락, 상위권 표본 편향을 설명합니다.
- 리뷰 가중 평가율과 게임별 평가율 요약을 구분합니다. 신뢰구간이 표본 선택 편향까지 해결하지는 않습니다.
- 가격의 시점·통화·무료 여부를 명시합니다. 긴 플레이 시간을 곧 만족이나 품질로 해석하지 않습니다.
- 출시 후 30·90일 비교는 필요한 시점 자료가 있을 때만 수행합니다. 누적 스냅샷으로 초기 반응을 복원하지 않습니다.

### 사건·계절성

코로나는 후보일 뿐 필수 사례가 아닙니다. 사건 시점·영향 경로·비교 가능성·자료 완전성으로 첫 사례를 선정합니다. 스포츠 행사·IP 영상 공개 등도 후보입니다. 가설·대상·기간을 먼저 정하고 변화가 없는 결과도 남깁니다.

전체 시장 변화, 신작, 할인, 업데이트, 대작 영향을 검토합니다. 전후 차이를 인과 효과로 단정하지 않습니다. 지역을 구분할 수 없다면 남·북반구가 섞인 자료를 “여름 효과” 대신 “6~8월 패턴”으로 설명합니다. 리뷰 언어를 국가로 단정하지 않습니다.

### 보유·미플레이 — 조건부 심층 분석

사용자×게임 보유·플레이 자료와 수집 방법을 검증한 경우에만 수행합니다. 보유는 구매와 다르며, 구매일이 없으면 구매 후 전환율을 계산하지 않습니다. 비공개·조회 실패·결측은 0시간과 구분합니다. 리뷰 작성자만으로 전체 보유자의 미플레이 비율을 구하지 않습니다.

단일 스냅샷은 현재 상태 분석에만 사용합니다. 이후 플레이 전환은 같은 표본의 반복 관측이 필요합니다. 공개·자발적 참여 표본의 한계를 표시하고, 식별자는 최소화하며 공개 결과는 집계 중심으로 제공합니다. 개별 사용자가 앞으로 플레이할지 예측하지 않습니다.

## 데이터 확보와 검증

| 자료 후보 | 역할 | 확보 전에 확인할 것 |
| --- | --- | --- |
| 최신 게임 기본 정보 | 게임 ID·출시일·유형·태그·가격 | 최신성과 누락, 통화, 관측 시점, 이용 조건 |
| 공식 연간·월간 차트 | 상업적 성과의 공개 근거 | 기간별 기준·자료 확보 방식·게임/DLC 구분 |
| 날짜가 있는 리뷰 | 반응 변화·평가 이유 | 조회 조건·완전성·수정·언어·구매 유형 |
| 사건·행사 기록 | 분석 시점·대상 설정 | 공식 근거·지역·사전 공개 여부 |
| 보유·플레이, 가격·이용 이력 | 조건부 분석 | 접근·이용 권한·표본·이력 존재 |

기존 [Steam Games Dataset 2025](https://www.kaggle.com/dsv/11017460)는 후보로 유지합니다. 게시 설명의 2025년 3월 스냅샷·MIT 표기는 원자료 검증과 별개이며 최신·장기 시계열 요구를 단독으로 충족한다고 가정하지 않습니다.

출처별로 필드·기간·갱신 주기·사용 및 재배포 조건을 기록하고 **질문 → 필요한 자료 → 가능한 답 → 한계 → 대체 범위**를 정리합니다. 허용된 수집 경로를 선택하며 원자료와 Tableau 패키지의 공개 가능 범위를 별도로 검토합니다.

확보 후에는 ID 유일성, 중복, 날짜·결측, 타입, 조인 전후 행 수, 태그 중복, 분모, 기간 경계를 검사합니다. 주요 SQL을 소량 수작업 또는 독립 집계와 대조하고 Tableau 결과와 일치시킵니다.

## 서비스 경험과 산출물

**월간 시장 브리핑 → 세부 게임군 탐색 → 경쟁작·평가 비교 → 기획 검토서**

| 산출물 | 구성 |
| --- | --- |
| 월간 브리핑 | 기준 월·관측일, 중요한 발견 3~5개를 목표로 하되 근거 없으면 억지로 채우지 않음; 지속 흐름·일시 변화·관찰 질문 |
| 탐색 대시보드 | 시장·흥행, 세부 게임군의 분포·집중도, 평가·경쟁작. 사건·이용 화면은 자료에 따라 추가 |
| 심층 보고서 | 선정된 사건 또는 계절성, 대안 설명, 민감도, 한계 |
| 기획 검토서 양식 | 아이디어·비교작, 확인 사실·미확인 사항, 위험, 검증 가설 2~3개, 진행·수정·보류 기준 |
| 재현 자료 | 출처·지표 명세, 정제 코드·SQL, 검증 기록, 실행 방법 |
| 취업 자료 | 실제 수행 범위·본인 판단·검증한 발견을 담은 소개 자료 |

대시보드는 근거 탐색, 보고서는 판단 전달 역할을 맡습니다. 제안은 **발견 → 수치·대상·기간 → 해석·대안 설명 → 행동 → 검증 방법**으로 씁니다. 자동 콘셉트 추천이나 성공 확률은 제공하지 않습니다. 분석에서 재미를 보장하지 않고 실제 프로토타입 테스트로 연결합니다.

## 실행 단계와 완료 기준

| 단계 | 산출물·완료 기준 |
| --- | --- |
| 1. 데이터 적합성·분석 설계 | 실제 필드·표본·기간·이용 조건 확인, 계산 가능한 질문과 KPI 정의, 첫 브리핑 대상 월·비교군 선정. 불가능한 질문의 조정 이유 기록 |
| 2. 작은 범위 검증 | 한 달 차트·게임 연결과 소수 경쟁작 리뷰 집계 검증. 누락·중복·날짜·분류 오류 확인 |
| 3. 기본 분석 | 재실행 가능한 Python·SQL 처리, 연도·월·세부 장르·평가 분석과 독립 수치 대조 |
| 4. 심층 분석·초판 | 사건 또는 계절성 사례, 조건별 결론 검토, 첫 월간 브리핑·대시보드·검토서 작성 |
| 5. 사용자 검토 | 개인·소규모 개발자가 비교작 선정과 검증 과제 도출에 활용하는지 확인, 혼동·오해 수정 |
| 6. 공개 파일럿 | 공개 권한·갱신·오류 표시·정정 이력 확인 후 배포. 실제 공개 URL과 검증 결과 기록 |
| 7. 운영 가능성 확인 | 다음 발행 주기를 재현하고 비용·소요 시간·자료 지연 대응을 점검. 포트폴리오에 실제 결과만 반영 |

운영 기준의 세부 수치는 데이터 확인 후 정할 제안입니다. 사용자 검토는 3~5명을 초기 목표로 하되 조사 시간, 비교작 적절성, 근거 추적, 다음 행동의 구체성을 평가합니다. 작은 표본을 전체 시장의 효과로 일반화하지 않습니다.

### 서비스 공개 전 확인

- 각 지표의 정의·출처·대상 수·기준일을 화면에서 확인할 수 있음.
- 주요 화면의 수치가 SQL과 일치하고 필터·빈 결과·소표본 표시가 작동함.
- 데이터·텍스트·패키지 파일의 공개 조건과 개인정보 처리를 확인함.
- 월간 발행 기준일과 자료 지연 처리 방식을 정함. 불완전한 자료를 최신 완료 자료처럼 게시하지 않음.
- 갱신 재실행, 수집 실패·누락 표시, 이전 발행본 보존, 정정 이력과 문의 경로를 마련함.
- 운영 비용·작업 시간과 유지 담당을 확인함. 공개 이후의 갱신 자동화는 실제 필요와 권한에 따라 구현함.

데이터 확보 가능성을 확인한 뒤 개발 일정을 구체화하며, 첫 브리핑과 기본 대시보드를 우선 완성합니다.
